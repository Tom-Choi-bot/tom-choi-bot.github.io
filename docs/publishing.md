# 뉴스·경제·청년 정책의 자동 발행 연결

현재 사이트는 세 분야의 독립 입력을 받아 하나의 매거진을 생성합니다. 앱 예약 작업의 설정을 변경하거나 새 예약을 등록하는 기능은 이 저장소에 없습니다. 기존 README의 Hermes 예약 설명과 앱의 뉴스·경제·청년 정책 작업이 어떻게 연결돼 있는지는 운영 설정에서 확인해야 합니다.

## 실행기가 갖춰야 할 조건

- 기존 일정과 프롬프트를 확인할 수 있어야 합니다. 이를 확인하지 않고 새 일정을 정하지 않습니다.
- 이 저장소에서 조사·원고 저장·Python 검사·빌드·Git 반영을 실행할 수 있는 인증된 환경이어야 합니다. 채팅 답변만 생성하는 예약 작업이라면 별도 실행기를 연결해야 합니다.
- GitHub 인증은 실행 환경의 기존 인증을 사용합니다. 토큰을 원고, 저장소, 프롬프트에 쓰지 않습니다.
- 원문 조사와 사실 확인은 실행기가 수행합니다. 아래 검사는 필수 필드·날짜·출처 URL과 형식을 검증하며, URL이 있다고 실제 사실을 검증한 것은 아닙니다.

## 경제

기존 `content/YYYY-MM-DD.json` 계약과 AGENTS.md를 유지합니다. 하루의 한국·미국·글로벌 시장 브리핑은 기존 방식대로 조사·검증합니다. 사이트는 원고에서 이슈별 고유 주소를 자동 생성합니다. 기존 날짜별 글과 차트는 그대로 남습니다.

## 뉴스·청년 정책

공통 필수 항목:

| 항목 | 의미 |
|---|---|
| `id` | 영문 소문자·숫자·하이픈으로 만든 안정적인 식별자 |
| `date` | 실제 확인 시점의 KST 날짜 |
| `checked_at` | 실제 원문 확인 시각. ISO 형식과 시간대 필수, 미래 시각 금지 |
| `title`, `summary` | 제목과 검증한 핵심 사실 |
| `context` | 배경과 근거 |
| `why_it_matters` | 영향·해석과 한계 |
| `watch_next` | 다음 확인점 |
| `source`, `url` | 직접 확인한 출처 이름과 원문 HTTP(S) 주소 |
| `published_at` 또는 `published_on` | 출처가 알려주는 발표 시각 또는 날짜. 정확히 하나만 사용 |

`summary`, `context`, `why_it_matters`, `watch_next`는 충실한 설명을 요구합니다. 20자 검사는 빈 내용에 대한 기본 방어일 뿐 품질 기준을 대신하지 않습니다. 홈의 짧은 요약 분량을 상세 조사 분량에 적용하지 않습니다.

발표 시각은 확인 시각 이후일 수 없습니다. 시각이 없는 `published_on`은 확인일 이전 날짜만 허용합니다. 당일 발표의 정확한 시각을 확인하지 못하면 임의 시각을 넣지 말고 발행을 보류하거나 이후 재확인합니다.

뉴스 추가 필수 항목:

- `category`: 국내 / 국제 / 사회 / 산업 / 과학기술 중 하나
- `event_on`: 실제 사건일. 발표일과 구분하고 확인일 이후를 허용하지 않음

정책 추가 필수 항목:

- `region`, `topic`: 대상 지역과 주거·취업·교육 등의 지원 분야
- `eligibility`: 연령·거주·소득·취업 등 확인한 자격 조건. 개인 자격은 단정하지 않음
- `benefit`: 지원 범위·금액·지급 방식과 조건
- `application`: 실제 신청 절차
- `exclusions`: 중복 지원·제외 조건. 확인 못한 사항은 확인 필요로 명시
- `documents`: 필요한 서류 설명의 배열. 미확인인 경우 그 사실 명시
- `apply_url`: 공식 신청 안내 주소
- `opens_on`, `deadline`: ISO 날짜. 확인되지 않았으면 필드 값을 `null`로 지정

정책 식별자는 같은 공고를 재확인할 때 유지합니다. 다른 확인일의 버전은 별도 상세 글로 남고, 정책 목록에서는 가장 최근 확인본을 보여줍니다. 접수 기간 안이라도 신청 가능 여부를 단정하지 않습니다. 날짜만 알려진 마감일 당일에는 마감 시각 확인이 필요하다고 표시합니다.

## 원고 입력과 배포 순서

저장소 루트에서 실제로 검증한 JSON 원고를 임시 경로에 준비한 뒤 실행합니다.

```sh
python3 scripts/intake.py --channel news --input /tmp/verified-news.json
python3 scripts/intake.py --channel policies --input /tmp/verified-policy.json
python3 -m unittest discover -s tests -v
python3 scripts/site.py --content content --output dist
```

`intake.py`는 형식 검사를 통과한 뒤 `content/<분야>/YYYY-MM-DD-id.json`에 원자적으로 저장합니다. 같은 입력은 두 번 실행해도 파일을 추가하지 않습니다. 같은 날짜·식별자의 다른 원고는 덮어쓰지 않습니다. 직접 검토한 정정에 한해 더 새로운 `checked_at`과 `--replace`를 사용합니다.

입력 저장은 Git 반영이나 배포를 수행하지 않습니다. 운영 실행기는 검사·빌드가 성공한 다음 이번 작업의 파일만 스테이징하고, 기존 인증으로 `main`에 커밋·푸시합니다. 현재 GitHub Pages 워크플로가 검사와 빌드를 다시 실행해 배포합니다. 동시 Git 작업은 운영 실행기에서 직렬화하고, 원격 변경을 안전하게 반영한 뒤 재검증합니다. 충돌 시 강제 푸시나 다른 원고 덮어쓰기를 하지 않습니다.

## 실패와 상태 확인

- 필수 입력에 문제가 있으면 빌드 출력 변경 전에 거부합니다. 한 분야의 실패 때문에 다른 분야의 검증된 원고를 삭제하지 않습니다.
- 홈은 경제의 자료 기준일, 뉴스·정책의 마지막 원문 확인일을 구분합니다. 실행 성공 시각을 임의로 표시하지 않습니다.
- 이전 자료에는 날짜를 유지하고 브라우저에서 최신 확인 필요 상태를 표시합니다.
- 공개 홈과 이번 글의 독립 주소에서 실제 내용이 보이는지 확인합니다. 커밋·빌드 성공만으로 배포를 주장하지 않습니다.
- `scripts/watchdog.py`는 매거진 홈의 당일 경제 카드와 날짜를 확인한 뒤 당일 날짜별 상세 브리핑을 열어 기존 섹션·원리 검사를 수행합니다. 이 검사는 뉴스·정책 예약의 성공을 보증하지 않습니다.

앱 예약 설정의 실제 수정과 실행 시험까지 끝나야 자동 연동 완료로 판단합니다. 저장소에 입력 경로가 있다는 것과 예약이 연결됐다는 것은 별개입니다.
